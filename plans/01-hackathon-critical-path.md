# VAPOR Hackathon Critical Path

This file is the execution specification for graph nodes N0–N9. It is ordered by dependency and judge value, not by code layer.

## N0 — Truth baseline and scope freeze
Objective: Turn the repo from an inflated readiness claim into a trustworthy execution baseline.

## N1 — Provider contract spike
Objective: Prove the smallest real Prava, Senso and Linq contracts before building around them.

## N2 — Minimum trustworthy security boundary
Objective: Make the demo path safe enough for a controlled sandbox, without claiming certification.

## N3 — Canonical data and financial state
Objective: Create one coherent migration history and durable state model for the golden path.

## N4 — Real Prava golden path
Objective: Make Prava central and visibly complete one sandbox purchase flow.

## N5 — Deterministic policy and approval state machine
Objective: Make VAPOR’s novel governance layer real, explainable and safe.

## N6 — Meaningful Senso and Linq track experience
Objective: Make partner technology change the user’s outcome rather than decorate it.

## N7 — Judge-facing product experience
Objective: Turn backend pieces into a self-explanatory three-minute product.

## N8 — Verification, deployment and observability
Objective: Create repeatable evidence and a stable judge URL.

## N9 — Submission and proof package
Objective: Convert the working product into judge-verifiable evidence before the portal deadline.
